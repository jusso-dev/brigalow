# Disposable homelab production qualification

The single-instance software/reference-container gates passed on the Linux
amd64 homelab. This is not a production go-live sign-off: real HSM/provider,
operator identity/TLS, independent security review and remaining OS advisories
still require qualification. No persistent service was left running.

Tested implementation: `4db39b85a203808b360b47fa492e751584370c9c`, based on
`66dd37e0df09870adc2e26d9370f865e04a316b4`. The
[machine-readable evidence](homelab-2026-11-17.json) records source hashes,
timings, scanner/database versions, remaining high/critical advisories and
cleanup. The starting application's hosted CI and dependency audit also
passed; the implementation's publication checks are separate from this
homelab evidence.

## Changes and verified behaviour

The runtime previously installed curl solely for its Docker health check,
bringing unrelated transport dependencies into the signing container. The
existing Rust HTTP client now implements `brigalow-server --healthcheck`:
fixed loopback port 8080, HTTP 200 required, four-second timeout, no proxy or
redirect, and no configuration/credential loading or new HSM session. Curl
and 14 dependency packages are absent from the rebuilt production image.

The full Compose gate now drives the actual production-mode server binary
through the pinned TLS proxy. It completes generated-IdP OIDC login across a
process restart, verifies an established session after another restart,
checks browser binding, single-use login, CSRF, role and tenant separation,
creates a test-purpose HSM key/policy/scoped credential, and invokes the real
`brig` CLI. OpenSSL independently verifies its signature and rejects modified
content. Disabling the key produces a persisted `key_binding` rejection with
no signature; token and session revocation reject subsequent access.

The native probe succeeds with an intentionally missing configuration path,
proving it does not load that configuration. Pausing only the disposable DB
makes readiness fail within its bound while `/livez` remains available;
unpausing restores readiness. The unit regression accepts 200, rejects 503,
redirects and connection failure. Changing the client to follow redirects
makes the regression fail; the original source was restored before the full
suite. These checks run in the existing CI `rust` job without narrowing any
other gate.

Compose's count includes repeated Rust executions, not 84 distinct acceptance
contracts. Python/OpenSSL assertions are additional. An earlier full homelab
run of the expanded flow also passed, before the native-probe hardening. Its
1,075.147-second duration and the final duration are not a controlled speedup:
source, test inventory and build-cache warmth differ.

The runner and production builder used pinned Rust 1.99.1. Docker and Compose
ran on homelab itself with explicit context `default`, so temporary bind
paths and loopback ports belonged to that host. The isolated runner had four
CPUs and 6 GiB; its private BuildKit builder had four CPUs, 8 GiB and one build
operation at a time. No host toolchain was installed, no active Docker context
was changed, and no public ingress or cloud resource was created.

The first packaging attempt hit Git's ownership guard in the disposable
runner; trusting only that task checkout inside the runner resolved it.
Scanner archive permission/tag staging errors were corrected before the
successful final scan. These were harness errors, not waived application
failures.

## OS package scan and remaining limits

Checksum-verified Trivy 0.76.2 scanned exported production images using the same
advisory database. OS packages only; all severities; no ignore file and no
`--ignore-unfixed`. Cargo lockfiles were unchanged by this implementation.

| Measure | Before | Hardened |
| --- | ---: | ---: |
| Installed OS packages | 106 | 91 |
| HIGH package/advisory findings | 104 | 37 |
| CRITICAL package/advisory findings | 1 | 1 |
| Distinct HIGH/CRITICAL advisories | 31 | 11 |
| HIGH/CRITICAL findings with a listed Bookworm fix | 0 | 0 |

Counts are package/advisory matches, not demonstrated remotely reachable
exploits. Removing curl also removes Kerberos, LDAP, SASL, SSH and other
unused transport dependencies. No runtime base upgrade was made: a separate
scan of pinned Debian trixie-slim still reported unfixed high findings.

The remaining critical entry is CVE-2023-45853. The
[Debian tracker](https://security-tracker.debian.org/tracker/CVE-2023-45853)
marks Bookworm's zlib ignored because the affected contrib/minizip code is
not built into its binary packages; this image has no minizip package. The
scanner entry remains in the evidence. Other remaining high findings are
also retained, with package versions and vendor status. Absence of a listed
fix is not an assurance that a package is safe, and no deployment risk
acceptance is implied by this report.

Production go-live still requires the actual vendor HSM/provider and backup
procedure, operator IdP/TLS and restricted database configuration, independent
review of the deployed image/configuration, and disposition of remaining OS
advisories. Only one server replica is supported. SoftHSM cannot qualify
hardware custody, HA/fencing, public trust, or compliance certification.

## Cleanup

`cargo clean` removed 10.7 GiB from the homelab workspace. The private BuildKit
builder and its compilation cache were removed, along with both disposable
Compose projects, their containers/networks/tmpfs volumes/tagged images,
scanner images, archives, generated test credentials and the temporary source
checkout. Newly downloaded base images were removed only when absent from the
initial inventory and unused. Shared caches were not pruned.

All 74 containers running before validation remained running afterward. No
task containers, networks, volumes or tagged images remained, and the private
temporary directory was removed. No permanent homelab service or port change
requires a handbook entry.
